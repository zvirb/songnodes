## Do
1. key_bpm.analyse(samples, sample_rate) -> {'bpm', 'bpm_confidence', 'key_camelot', 'key_name', 'key_confidence', 'method', 'method_version'} and analyse_file(path) for WAV/MP3/FLAC. Use essentia (KeyExtractor profileType='edma', RhythmExtractor2013) if a wheel installs on Python 3.15; otherwise librosa (chroma CQT with Krumhansl and EDM-weighted key profiles; beat tracking with tempo prior) and say why in the PR. Return None for a value it cannot measure rather than guessing.
2. BPM: fold half and double time into 70 to 180 using a dance-music prior (house 118 to 130, techno 125 to 150); report the folded value and keep the raw one in the result.
3. synthetic_audio.py generates deterministic test clips with numpy at test time (nothing binary is committed): a four-on-the-floor kick plus hats at an exact BPM over a sustained chord progression in a known key, 30 s, 44.1 kHz. At least: 124 BPM A minor (8A), 128 BPM C major (8B), 174 BPM F minor (4A), 122 BPM D-flat major (3B), a 120 BPM clip with a 2 % tempo drift, and a clip played at half time (64 BPM) that must fold to 128.
4. Tests: each synthetic clip gives BPM within plus or minus 1 and the exact Camelot key (allow the relative major/minor only for the drift clip, and say so); silence returns None for both; a 5 s clip returns low confidence. Mark slow tests and keep the suite under two minutes.
5. scripts/benchmark-key-bpm.py FOLDER [--csv out.csv]: for each audio file whose tags carry a key and BPM (read with mutagen: TKEY/initialkey, TBPM/bpm; also Mixed In Key style '8A - A minor' comments), analyse it (optionally only the first 30 s with --clip 30) and print exact-key %, key-within-one-Camelot-step %, BPM within plus or minus 1 %, BPM off by double or half %, and a per-file CSV. It runs on the owner's laptop on his own music; it never uploads anything.
6. docs/audio-analysis/key-bpm.md: method, the synthetic test set, how to run the benchmark (Git Bash on Windows), and its result fields.
