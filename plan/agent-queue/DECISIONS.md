- D022 - 2026-11-21 12:19-13:00 Melbourne, Markus in chat ('cut over ... all three now, in chat'), task WQ00203, run chat-markus-20261121-1219: qdb/queue.db is now the SongNodes queue store (rule Q026). Design: one database per checkout, for the branch named in qdb/queue-db.json only (main). Reason: the Q011 design keeps execution state per branch and per worktree; a single shared database for every branch would carry one branch's claims into another (the exact leak Q011 prevents). Safety: every write is inside the existing .mutex, builds a private temp database (journal_mode=TRUNCATE), copies it beside qdb/queue.db and renames it over the shared file; each write bumps a generation and refuses (BUSY) if another writer moved it since the load (covers machines that do not share the mutex); reads use a private copy. state.json stays a full mirror and its hash is stored in the database, so a write to state.json by anything else is refused with the fix named, a crash between the database write and the views is recovered by `repair`, and a Queue Monitor shadow build over the file falls back to the mirror and is replaced at the next write. The tasks and status tables match the monitor's own shadow build row for row (checked on today's data: 207 and 288 rows identical). `verify` now refuses the agent that staged the proposal.
