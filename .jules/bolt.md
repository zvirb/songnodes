## 2026-10-24 - Pre-computing edge transition costs in A* search loops
**Learning:** In graph pathfinding algorithms (such as A* for DJ setlists), evaluating static transition properties (e.g. key compatibility, BPM difference penalties, synthetic edge checks) during neighbor expansion inside a progressive relaxation loop causes millions of redundant function calls and dictionary lookups. Pre-computing a static adjacency structure (`prepare_adjacency`) before starting the search loop reduces search execution time by ~50%.
**Action:** When working with A* or graph search algorithms that perform multiple search attempts or relaxations over a fixed graph, pre-calculate static edge costs and metadata once into an optimized adjacency lookup structure before entering the priority queue expansion loop.
