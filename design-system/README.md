One system for **SongNodes** (the track-graph platform in the `songnodes` repo) and the **music library** (Naarm Set Builder and its weekly run). Every page, panel and artifact for either product is built from these tokens, classes and patterns, so the same thing always looks and reads the same.

The look: Elektronauts' charcoal ground and plain reading type, YourEDM's single-colour cards, The Ghost Production's soft card shapes, and the energy/transition vocabulary of the Naarm Set Builder.

## Use it

- Load `tokens.css`, then `components/bundle.css`, then `components/bundle.js` (defines `window.SongNodes`). Fonts are self-hosted in `fonts/` and declared in `tokens.css`; nothing loads from a CDN.
- Run `SongNodes.prefs.init()` inline in `<head>` before first paint so the saved theme, text size, density and motion apply without a flash.
- Build from the classes in each component's guidelines. Never write a colour, font size, radius or shadow literal; use a token. Read the component's guidelines before using it.
- Format every date, time, duration, count and BPM through `SongNodes.format`; map every backend status through `SongNodes.status(raw, domain)`; judge transitions with `SongNodes.compat`, `bpmStep` and `energyStep`.
- To change the system, edit `source/build_tokens.py` (colours, type, scales) or `source/css/*.css` / `source/bundle.src.js`, then run `python3 source/build_tokens.py .` and `python3 source/build_bundle.py` from this folder. The generator prints a contrast report; nothing ships with a failing pair.

## Content fundamentals

- **Voice:** a knowledgeable booth-mate. Plain, direct, specific. "Energy climbs one point at a time, then drops two or three after a peak." Never cute, never apologetic, never an exclamation mark.
- **Case and spelling:** sentence case everywhere, en-AU spelling (colour, analyse, centre). Uppercase only through the `label` style, and never typed in caps.
- **Buttons:** a verb plus its object: "Build set", "Copy tracklist", "Delete set". One primary button per view.
- **Numbers:** "1,284 tracks", "124 BPM", "8A", "6:12", "92 min", "+2 BPM", "−1" (true minus). Missing values are an en dash "–", never "N/A" or "Unknown".
- **Time:** Australia/Melbourne is the time zone of record, 24-hour: "24 Oct 2026, 06:00 AEDT", "Sat 24 Oct". Relative times ("3 h ago") always carry the absolute stamp in a tooltip.
- **No emoji** anywhere in the interface: not in buttons, tabs, empty states or toasts. Status glyphs (● ◐ ○ ▲ ✕ ↻ –) and Lucide icons do that work.
- **Confirmations** name the object and the consequence: "Delete “Peak time Friday”? This removes the set for everyone. Tracks stay in the library." Never `alert()` or `confirm()`.

The full rules are in *Writing and content*.

## Visual foundations

- **Ground and surfaces:** `bg` charcoal, then `surface-1` (panels, cards), `surface-2` (raised parts, table headers), `surface-3` (pressed, tracks), `sunk` (inputs). Dividers use `line`; control borders use `line-strong`.
- **Text:** `fg` primary, `fg-2` secondary, `fg-3` tertiary and the dimmed lead-in of titles.
- **Thin–bold titles:** every page and section title is a regular dimmed lead-in plus a bold title: `<h1 class="sn-title title-l"><span class="sn-lead">Set builder:</span> Peak time Friday</h1>`. Titles are Sora, body is Inter, data (BPM, keys, times, IDs) is JetBrains Mono with tabular figures.
- **Brand:** lavender `brand` marks SongNodes itself: the wordmark, the one primary button, the focus ring and selection. It never means a status. The marker for "now" (playing track, current slot, today) is amber `now`, so it is never confused with selected.
- **Modules:** eight areas, each with one identity hue: Graph, Library, Set builder, Pathfinder, Key & mood, Sources, Pipeline and Services (`mod-<key>`). The hue appears on the module's drawer icon, on every text link that leads to it, and on its cards. Scope a region with `sn-m-<key>`.
- **Links** take the colour of where they lead and are always underlined (`sn-link sn-m-<key>`); a link that leads nowhere module-specific uses `link`.
- **Tonal cards:** a module card (`sn-card sn-card--tonal`) is all shades of its module hue (fill `mod-<key>-bg`, border `-line`, text `-ink` and `-muted`, chips and secondary buttons `-raised`). Only status colours break out of it.
- **Status** (`status-ok|fair|warn|bad|info`) only ever means state, and always comes with a glyph and a word. Transitions use `compat-perfect|compatible|possible|clash` (● ◐ ○ ✕). Traffic-light colours in every theme, so the glyph and word must always be there.
- **Energy 1–10** is a ten-step heat scale (`energy-1` deep indigo to `energy-10` amber), drawn as the ten-segment bar with gaps after 4 and 7 (Low, Building, High tiers), always with the number.
- **Keys** are Camelot codes with a wheel-colour dot (`key-1a` … `key-12b`; minor darker, major lighter), standard mapping (8A = A minor, 8B = C major). Detail views add the name.
- **Shape:** `radius-chip` 4 (chips, tags), `radius-control` 8 (buttons, inputs), `radius-card` 14 (cards, tiles), `radius-sheet` 18 (dialogs, drawers), `radius-pill` (status pills, switches).
- **Depth:** cards rest at `shadow-1` with a hairline border. Only floating layers rise: `shadow-2` for menus and popovers, `shadow-3` for drawers and dialogs over the `overlay` scrim.
- **Space and density:** 4px scale (`space-1` … `space-16`); comfortable 40px rows by default, compact 32px as a saved per-person option; 44px touch targets on touch screens.
- **Themes:** Dark (default), Light and Booth (pure black, larger type, 7:1 text, for dark rooms and distance). System follows the OS. Text size S/M/L/XL scales everything through `rem`.
- **Motion:** 120ms for state changes, 200ms for drawers and dialogs, 320ms at most for charts. Nothing animates in on load. Reduced motion stops all of it, including spinners and skeletons.
- **Focus:** a 2px solid `focus` ring with a 2px offset on every interactive element (3px in booth).
- **Never:** gradients, glows, glass, coloured left-border accent cards, emoji, status colours on categories, or a second primary button.

## Iconography

- Lucide (ISC licence), 2px stroke, round caps. The 109 icons in use are in the Icons asset group, copied from lucide-static 1.53.0; SongNodes uses the matching `lucide-react`.
- In code, use `SongNodes.icon(name, {label})` or `lucide-react`. Icons inherit `currentColor`; the asset files are drawn in neutral grey `#8a8a8a` for reference only.
- One meaning per icon (see *Identity and iconography* for the full meaning table). Module icons: Graph `share-2`, Library `library-big`, Set builder `list-music`, Pathfinder `route`, Key & mood `piano`, Sources `radio-tower`, Pipeline `activity`, Services `plug`.
- Icon-only buttons always carry an `aria-label` that names the action and its object.
- There is no logo. The wordmark is "SongNodes" set in Sora 800 in `brand`. Never draw a mark.

## Consuming this system (generated — do not edit)

Every path named below is under `project/` in this design system: read `project/api/tokens.md`, not `api/tokens.md`.

`components/bundle.js` defines `window.SongNodes` (92 components); `components/bundle.css` is its stylesheet; `tokens.css` is every token as a CSS variable plus `@font-face` for the fonts. `components/bundle.css` reads its variables from `tokens.css`. Build any UI by mounting these components; never hand-build a control or draw an icon the system provides.

- **Standalone page:** inline `tokens.css` and `components/bundle.css` in a `<style>`, then `components/bundle.js` as a classic script (a file containing `</style`, `</script` or `<!--` breaks an inline element: write the sequence `<\/style`, `<\/script` or `\x3C!--` in your copy, or load that file by URL).
- **Design canvas:** bring `tokens.css`, `components/bundle.css`, `components/bundle.js` and `components/index.d.ts` (for the editor’s props panel) onto the canvas in full, as the canvas type’s design-system components reference says (a server-side copy first where it offers one); in each artboard that uses this system, right after the `support.js` line, load `tokens.css` first, then the stylesheet, then the script; mount with `<x-import component-from-global-scope="SongNodes.<Comp>" …>`.
- **Slides deck, or any surface that cannot run the bundle:** tokens and fonts — the values are on `api/tokens.md`; the deck takes `tokens.json` by file path for its colour pickers, and fonts as “Fonts” below says.

Fonts: `tokens.css` loads each font from its file, by path.

- **Design canvas:** copy `fonts/sora-latin-wght-normal.woff2`, `fonts/inter-latin-wght-normal.woff2`, `fonts/inter-latin-wght-italic.woff2` and `fonts/jetbrains-mono-latin-wght-normal.woff2` to the same paths under the canvas’s `project/ds/<folder>/` (`<folder>` is the folder you install this system under; `fonts/sora-latin-wght-normal.woff2` lands on `project/ds/<folder>/fonts/sora-latin-wght-normal.woff2`), in the same call that installs this system; the copy of `tokens.css` that each artboard links loads them from there. If the install’s reply leaves a font out, bring that font in as for any other page.
- **Slides deck:** for each family you use in the deck (`faces` holds at most the number of typefaces Slides’ `deck-files.md` gives), install its file with the system and name the path it lands on as that family’s `src` in `project/deck.json` `faces`, under the key in the Slides column. A deck takes a font as a file only under the rule in Slides’ `fonts.md` (no space or leading underscore in its path, for two): any other font, or one kept by id, is uploaded as `fonts.md` says.
- **Any other page:** one file per family is enough (below: the upright face nearest regular weight; bold and italic synthesize). Fetch it as the fetch column says (Artifact tool `read`, that id or path as `path`), upload it as an asset (`publish`, `file_path`, `asset:true`) and declare it with an `@font-face { font-family: "<family>"; src: url(<uploaded>) }` rule.

**Read, per thing:** a component’s props, parts and examples: `api/components/<Comp>.md`; token values: `api/tokens.md`; stored assets and their paths: `api/assets/<Group>.md`. After this README, fetch the cards and fonts you need in ONE message as parallel calls — none depends on another.

**Two rules.** Before you use a thing — a component, a token group, an icon, an asset — read its card from the index below; a value you did not read from a card is a guess. `tokens.json`, `manifest.json`, `components/index.d.ts` and `design-system.json` are sources for tools: hand them over. `components/<Comp>/README.md` and `assets/<Group>/README.md` are the long-form second read a card links to; `SKILL.md` and `artifact-type/` beside them are authoring guidance, not needed to consume the system.
