Section 6: Storage Hubs & Physical Topologies

SongNodes coordinates 8 storage hubs, balancing ACID relational guarantees in PostgreSQL with sub-50ms graph queries in Memgraph and resilient local offline storage in the browser and SQLite.

PostgreSQL Bronze Ingestion Store (postgres_bronze) relational_db · Docker Volume pgdata (PostgreSQL port 5432)

Raw, immutable capture of external scraped playlists and track items.

Lock / Concurrency:
Transaction-scoped MVCC; unique constraints on (source, source_playlist_id)
Authoritative: Yes, for un-normalized raw source payloads.
PostgreSQL Silver Normalized Store (postgres_silver) relational_db · Docker Volume pgdata (PostgreSQL port 5432)

Deduplicated, enriched tracks, verified sequential transitions (1..N), and provider consensus evidence.

Lock / Concurrency:
Row-level locks during Celery enrichment worker drain; idempotent by job_id
Authoritative: Yes, authoritative single source of truth for all verified track pairings and metadata consensus.
PostgreSQL Gold Projection Store (postgres_gold_projection) relational_db · Docker Volume pgdata (PostgreSQL port 5432)

Denormalized, read-optimized projection of tracks and transitions for fast API queries.

Lock / Concurrency:
Maintained by projection_consume Celery worker; rebuildable from silver.
Authoritative: No, disposable derived projection.
Memgraph Graph Database (memgraph_gold_graph) graph_db · Docker container songnodes-memgraph (Bolt port 7687)

In-memory graph topology enabling sub-50ms Cypher queries for harmonic pathfinding and transition traversals.

Lock / Concurrency:
Internal Memgraph Bolt transaction concurrency
Authoritative: No, projected from PostgreSQL silver transitions.
Redis Broker, Lease & Telemetry Store (redis_queue_cache) in_memory_kv · Docker container songnodes-redis (port 6379)

Celery job queue broker, worker lease management, rate-limiting counters, and real-time scraper window telemetry.

Lock / Concurrency:
Redis single-threaded atomic operations; TTL-backed leases
Authoritative: No, transient operational state.
musicLibrary Curated SQLite Database (musiclibrary_sqlite) sqlite_db · e:\musicLibrary\db\dj_library.sqlite

Local offline curated DJ database holding crates, appearances, rotation history, and setlists.

Lock / Concurrency:
File-based SQLite locks; single-writer batch rebuild via pipeline/run_weekly.py db
Authoritative: Yes, authoritative for DJ crate assignments and High/Standard/Archive rotation lifecycle.
Filesystem Ledger & Export Volumes (filesystem_ledgers_outputs) filesystem · e:\musicLibrary\ledger\, e:\musicLibrary\outputs\, frontend\public\data\

Immutable weekly ledger snapshots, crate CSVs, Rekordbox XML exports, and static sync files.

Section 7: Inter-Page & Inter-Process Protocols

1. Dual-Persistence & Offline Outbox Protocol

SetBuilderPage.tsx commits changes synchronously to browser LocalStorage (songnodes_saved_sets) on every drag-and-drop or slot edit. Asynchronously, mutations are posted to POST /api/v1/library/sets. If the network or backend is offline, the local draft persists indefinitely, alerting the user with an honest status banner.

2. Streaming OAuth Popup Handshake (postMessage)

Music streaming authentication for TIDAL and Spotify operates via secure popup windows. A cryptographic nonce state is stored in sessionStorage. Upon user approval, OAuthCallback.tsx validates the nonce and securely transmits the token to the parent opener using window.opener.postMessage({type: 'OAUTH_SUCCESS', token: ...}, window.location.origin). Server credentials are encrypted on disk via SEC6; no plaintext secrets reside in browser storage.

3. OWASP CSV Formula Injection Guard (DR-033)

All CSV exports across SongNodes and musicLibrary pass through the OWASP formula injection guard: any string cell whose leading character is =, +, -, @, tab, or carriage return is prefixed with a single apostrophe ('). This prevents spreadsheet execution while preserving raw numeric sorting on BPM and energy values.

Section 10: Architectural Gaps & Proposed Modules

GAP-01: Disconnected Rekordbox Booth Performance Feedback Loop High

Sets are exported to Rekordbox XML (outputs/rekordbox_musicLibrary.xml), but actual live DJ booth history (played order, timestamps, crowd reactions) remains trapped on USB drives / HISTORY.m3u8 and never returns to SongNodes.

Impact:
Live transitions performed at gigs do not increment occurrence_count in silver_track_transitions; rotation aging algorithms cannot observe real play history.
Fix: Implement Pioneer USB Booth History Ingester (services/library/booth_history.py + /sets/history view) that parses Pioneer HISTORY.m3u8 files, updates track play history, and commits verified live transitions into silver_track_transitions.
GAP-02: Dual Storage Disconnect (PostgreSQL library.* vs SQLite dj_library.sqlite) High

The weekly pipeline writes to SQLite (dj_library.sqlite), while the SongNodes web application writes to PostgreSQL schema library.*. The sync script only copies a static JSON file (data/music-library.json).

Impact:
Curator tag edits or crate adjustments made in the web UI do not propagate back to the weekly SQLite ledger, leading to split-brain library state.
Fix: Deploy Bi-Directional Library Synchronization Bridge (services/library/bridge.py) with checksum reconciliation and single-writer lease enforcement.
GAP-03: Missing Audio Fingerprint & AcoustID Transition Segmenter Medium

Pairing transitions rely exclusively on scraped textual tracklists (1001Tracklists, MixesDB). Recorded DJ audio mixes cannot be automatically segmented or verified against audio fingerprints.

Impact:
Un-tracklisted DJ sets and radio broadcasts cannot be mined for transitions; track version mismatches (e.g. Dub Mix vs Vocal Mix) cannot be validated by audio waveform.
Fix: Deploy Essentia / Chromaprint Audio Segmenter worker (services/audio-analysis/segmenter.py) that ingests recorded audio mixes, detects transition crossfades, and queries AcoustID for automated setlist synthesis.
GAP-04: Unwired Scraper Target Queue Feedback Medium

When a curator adds an artist target in /library or /sources/targets, it writes to target_tracks in PostgreSQL. However, the standalone musicLibrary pipeline reads static config/sources.json and does not poll this queue.

Impact:
High-priority targets added by the user remain dormant until manually scraped, creating an operational bottleneck.
Fix: Wire automated target dispatcher cron that syncs PostgreSQL target_tracks directly into the weekly scraper schedule.
GAP-05: Outbox Projection Lag Invisibility Low

Graph projection (projection_consume) polls PostgreSQL outbox every 15 seconds. During bulk scraping, projection lags behind silver ingestion with no real-time push notification to the UI.

Impact:
Users browsing /library or /paths see stale transition data without an indicator that background projection is currently catching up.
Fix: Add WebSocket or Server-Sent Events (SSE) notification stream on /api/v1/outbox/status that broadcasts active projection lag and displays a non-intrusive FreshnessStamp pill.

Four Proposed Single-Purpose Modules (<500 LOC)

MOD-01: Booth History Ingester ~340 LOC

Target Users: Performing DJ, Music Curator · Verb: Harvest

Parses sequential timestamps from Pioneer booth exports, matches track titles against silver_enriched_tracks, increments rotation counters, and commits live transitions into silver_track_transitions.

Inputs: Pioneer DJ HISTORY.m3u8, Rekordbox USB play history, Venue metadata
MOD-02: Realtime Graph Outbox Daemon ~280 LOC

Target Users: Platform Admin, Graph Specialist · Verb: Stream

Replaces 15-second polling projection with sub-second event-driven Bolt synchronization directly updating Memgraph nodes and transition edges.

Inputs: PostgreSQL LISTEN/NOTIFY events on silver_track_transitions, Memgraph Bolt connection
MOD-03: Bi-Directional Library Bridge ~410 LOC

Target Users: Curator, Data Pipeline Engineer · Verb: Reconcile

Enforces single-writer locks, compares table checksums, bi-directionally syncs crate memberships and user tags, and exports fresh static JSON.

Inputs: PostgreSQL library.* schema, SQLite dj_library.sqlite, music-library.json
MOD-04: Audio Preview Stream Caching Proxy ~290 LOC

Target Users: Performing DJ, Selector · Verb: Cache

Downloads and caches 30-second audio preview snippets locally, generates waveform peak JSON arrays, and streams audio offline with zero external network latency.

Inputs: Deezer / TIDAL 30s preview stream URLs, Local disk volume /var/songnodes/audio
